# InterCOM 0.3.22

## Improvements

- Scheduled maintenance checks the CleverReach connection even when no newsletters are being sent. Monthly access tokens renew seven days before expiry, and each newly issued refresh token is saved for the next renewal.
- Backend Options and the administrator dashboard show the OAuth client ID, verified CleverReach account, localized access-token expiry with timezone, last connection check, last successful renewal and planned renewal date. Connection messages explain when automatic renewal needs attention.

## Fixes

- Preserve newly issued token pairs in encrypted storage before account validation, so temporary validation failures can recover without replaying the previous refresh token.
- Keep concurrent renewal requests behind a shared durable claim. Lost/interrupted exchange responses require recovery, and late responses cannot replace credentials supplied by a manual reconnect.
- Keep automatic renewal bound to the pinned account and outside mailing transactions, preventing unrelated rollbacks from discarding rotated credentials.

## Upgrade notes

Adds a connection-renewal metadata/pending-credentials table. Existing encrypted credentials, account identity, mailing reservations, settings and permissions are preserved.
Enable Task – InterCOM and an InterCOM scheduled task, backed by a working server cron trigger. Simulation pauses renewal. The backend warns about disabled scheduling and connection checks older than 48 hours.
Before deployment, confirm pre-expiry renewal and refresh-token rotation with a controlled CleverReach connection. Automated tests use synthetic provider responses.

## Validation

- Full isolated CI passed: 152 PHPUnit tests, 21 frontend tests, native Joomla scheduler failure recovery, HTTP security/settings checks, and fresh/synthetic/public-package upgrade checks with Database maintenance validation.
- Simulated 90 days without newsletter activity renewed on days 23, 46 and 69 using each newly rotated refresh token. Recovery checks cover validation failure, competing requests, unknown/interrupted exchanges, account mismatch and manual credential replacement.
- Backend rendering checks cover English/Danish text and date formats, timezone conversion across daylight-saving changes, HTML escaping and secret exclusion.
